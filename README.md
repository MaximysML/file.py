# Discord Bot Relay

Консольный Python-клиент для общения **собственного бота** с выбранным ботом
в текстовом канале Discord. Поддерживает ручные запросы, отображение ответов,
префикс-инструкцию и ограниченную цепочку «продолжай».

## Запуск

Требуется Python 3.10+.

```sh
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python bot_relay.py
```

1. Создайте приложение и **бота** в Discord Developer Portal. В разделе Bot
   включите **Message Content Intent** и **Server Members Intent**.
2. Пригласите своего бота на сервер со scope `bot` и правами View Channel,
   Send Messages, Read Message History. Пригласите и целевого бота.
3. В Discord включите режим разработчика и скопируйте ID текстового канала.
4. При запуске введите токен (ввод видимый), ID канала и ID или точное имя
   целевого бота. При совпадении имён используйте ID.
   Можно передать токен через переменную окружения `DISCORD_BOT_TOKEN`.
   Токен виден при вводе: не записывайте экран и не показывайте окно другим.
   Программа не сохраняет его в файлы и не выводит повторно.
   Никогда не публикуйте токен и не используйте токен обычного аккаунта.

## Команды / встроенный промпт-справка

Управление остаётся **в консоли**, без отдельного графического интерфейса.
Цветные панели показывают подключение, исходящие команды и ответы; во время
ожидания отображается индикатор. Текст ответов не интерпретируется как разметка.

`/ask` и `/think` отправляются **самим ботом** в канал в виде обычного
текста: `@целевой_бот /think запрос`. Обычный ввод превращается в `/ask запрос`.
Это не вызов зарегистрированных slash-команд Discord. Остальные команды
(`/rounds`, `/prompt`, `/help` и т. д.) управляют программой локально.
Текст продолжения отправляется без добавления `/ask` или `/think`.

| Команда | Назначение |
| --- | --- |
| `/ask текст` или просто текст | Бот отправит `/ask текст` и покажет один ответ |
| `/think текст` | Бот отправит `/think текст`, покажет ответ и автоматически продолжит |
| `/rounds N` | Число продолжений для `/think`: 0–10, по умолчанию 1 |
| `/continue текст` | Задать текст продолжения, по умолчанию «продолжай» |
| `/prompt текст` | Инструкция перед каждым новым запросом |
| `/prompt off` | Сбросить инструкцию |
| `/help` | Вывести справку |
| `/quit` | Завершить программу |

Пример:

```text
/prompt Отвечай по-русски. Продолжай рассказ только по запросу.
/rounds 2
/think Придумай начало истории про космос
/ask Как зовут главного героя?
/quit
```

## Ограничения

- Многие Discord-боты **игнорируют сообщения других ботов** либо принимают
  только slash-команды. Реле не обходит эти ограничения и не вызывает
  slash-команды от имени пользователя. Нужен бот с поддержкой текстовых
  запросов от ботов; одного его имени недостаточно для интеграции.
- `/think` — локальный режим, а не доступ к скрытым рассуждениям. Целевому
  боту отправляется текстовая команда `/think` вместе с запросом. Метка относится только к его
  опубликованному ответу. После него реле отправляет «продолжай».
- На каждый запрос берётся первое новое сообщение выбранного бота в канале.
  Вложения выводятся ссылками, embeds — текстом. Редактирования, потоковые
  обновления и ответы из нескольких сообщений не объединяются. Используйте
  отдельный тихий канал: чужой параллельный ответ может быть принят за ваш.
- Ответ выводится в консоль, не пересылается вторично в Discord. Между
  продолжениями пауза 2 секунды; через 90 секунд без ответа цепочка прекращается.
  Лимит Discord — 2000 символов вместе с упоминанием и инструкцией.
- Не запускайте встречные реле или рассылки. Работайте с разрешения владельца
  сервера. Ctrl+C завершает программу в том числе во время ожидания ответа;
  новые команды консоли принимаются после окончания текущей цепочки.

## Тесты

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют локальную обработку команд, инструкций и ответов. Для проверки
сетевого обмена нужен реальный сервер, токен и совместимый целевой бот.

## API-прокси для программ-клиентов

```sh
source .venv/bin/activate
export RELAY_API_KEY='replace-with-a-long-random-key'
python bot_relay.py --server --port 8000
```

При старте введите токен, канал и целевого бота как обычно. Сервер запускается
после подключения Discord. По умолчанию слушает `0.0.0.0`; API требует
`Authorization: Bearer <RELAY_API_KEY>`. Не публикуйте его без HTTPS и сетевой
защиты. Для работы только на своём компьютере задайте `--host 127.0.0.1`.

В ZCode, DeepSeek Harness или другом клиенте, **если он поддерживает настройку
OpenAI-compatible API**, задайте:

- Base URL: `http://localhost:8000/v1` при локальном запуске (для удалённого
  сервера — его настоящий доступный адрес, не localhost).
- API key: значение `RELAY_API_KEY`.
- Model: `discord-relay`.
- Streaming: **выключен**.

Совместимость с конкретными версиями перечисленных приложений не проверена.
Реализованы `GET /v1/models` и `POST /v1/chat/completions`, не Responses API,
не Anthropic API. Передаются текстовые сообщения и function tools.

```sh
curl http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $RELAY_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"discord-relay","stream":false,"messages":[{"role":"user","content":"Привет"}]}'
```

### Как работает промпт и доступ к инструментам

В серверном режиме реле отправляет **`@целевой_бот ПРОМПТ + tools + история`**,
без добавления `/ask`. Используется настоящее упоминание по ID. Встроенный
промпт в `proxy_server.py` объясняет команды именно **обрабатывающему боту**.
Описания и параметры инструментов берутся из `tools`, присланных клиентом.

Бот может вернуть строго JSON вида:

```json
{"tool_calls":[{"name":"open_url","arguments":{"url":"https://example.com"}}]}
```

Прокси преобразует его в OpenAI `tool_calls`. Имя должно присутствовать в
переданных инструментах. **Выполняет инструмент программа-клиент**, а не прокси:
она проверяет параметры, разрешения, показывает подтверждение и передаёт
результат следующим запросом с ролью `tool`. Именно клиент может предоставлять
открытие сайтов, программ, терминал и файлы. Названия инструментов определяет
клиент; `open_url` здесь — лишь пример. Без инструментов доступа к ОС нет.
Не выдавайте непроверенным ответам бота бесконтрольный доступ к компьютеру.

Ограничения: только один активный API-запрос (остальные получают 429),
90 секунд ожидания ответа, первое сообщение целевого бота, **2000 символов
на весь исходящий текст с упоминанием**. Длинные истории/схемы инструментов
отклоняются с 400, а не обрезаются. Это существенно ограничивает применение
в coding harness: полноценные большие контексты через этот транспорт пока
не поддерживаются. Нет streaming, изображений, автоматической сборки
редактируемых ответов или серверного исполнения инструментов. Для работы
нужен целевой бот, принимающий сообщения от других ботов.
